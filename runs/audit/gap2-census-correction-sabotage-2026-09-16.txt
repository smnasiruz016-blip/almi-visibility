METHODOLOGICAL FINDING (owner ruling, recorded precisely and no further)
  the census implementation scans its own source file as part of the census population, so mutating
  the implementation can alter the population and the counts as well as the behaviour under test.
  Runs 1 and 2 (header above) are kept. No inference is drawn from either: a refused or contaminated
  run says nothing about whether the detector is safe or unsafe, in either direction.
  Run 3 (above) avoided the contamination by assembling the injected tokens from single characters.
  That is a workaround, not a method, so run 4 (below) replaces it with a controlled one.

    text of src/evidence/store.mjs — through `sources`; the census reads nothing else, so its own
    source file is not in the population the test judges, whatever is done to the implementation.
  · the totals read mid-limb come from a snapshot of every src/ bin/ tools/ .mjs index blob captured
    BEFORE any damage, passed through `sources`; the damaged file on disk is never scanned.
